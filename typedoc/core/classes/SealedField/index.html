SealedField

@webda/core

Class: SealedField<T>

Defined in: packages/core/src/models/sealed.model.ts:80

A model field sealed end-to-end to a user public key

The server writes the value with the recipient public key (ECDH-ES P-256 + HKDF-SHA-256 + AES-256-GCM, see src/sealed/) and can never read it: there is no get()/open() here, only the recipient devices open it with their private key. The stored data is the envelope { v, kid, epk, iv, ct }, a public output, bound by the AAD modelType|uuid|field|kid to its record, attribute and recipient key.

A client opens it with openValue(envelope, recipient, fieldAad(modelType, uuid, field, envelope.kid)) where:

  • modelType is the model identifier (useModelId(model), e.g. "Webda/Note")
  • uuid is String(model.getPrimaryKey()) (composite keys are joined with the model separator, _ by default)
  • field is the attribute name (e.g. "content")
  • kid is the envelope kid

The recipient is seal(value, { user }), else the model getSealedRecipient(field) (the owner for an OwnerModel), else the model getOwner().

A client can also seal the value itself (KeyVault.seal) and store the envelope with the set action (<Model>.<Field>.Set, PUT <model>/{uuid}/<field>.set), authorised by the model canAct("<field>.set"): the server checks the envelope shape and that it is sealed to the recipient active key, it cannot check the content.

class Note extends OwnerModel {
  content: SealedField<{ title: string; body: string }>;
}
await note.content.seal({ title, body }); // sealed to the owner
await note.save();

The size of a client-sealed envelope is capped by SealedFieldParameters.maxSize (1 MiB by default), configured per attribute: models.<Model>.behaviors.<attribute>.maxSize.

Defined in: packages/core/src/models/sealed.model.ts:151

Store an envelope sealed by a client (KeyVault.seal) and save this field only (a patch of the attribute)

Exposed as <Model>.<Field>.Set, authorised by the model canAct("<field>.set"). The envelope must be well formed, at most SealedFieldParameters.maxSize ciphertext characters, and sealed to the active key of the recipient (resolved as for SealedField.seal); the server cannot check that it opens, the AAD the client used (modelType|uuid|field|kid) is only verified by the recipient.
