count()​

count(filter?, params?, options?): Promise<CountResult>

Defined in: packages/models/src/repositories/repository.ts:185

Count the objects matching a filter

repo.count("status = 'open'", undefined, { max: 10000 }); // { value: 1234, relation: "eq", native: true }

ORDER BY, LIMIT and OFFSET of the filter are ignored; DELETE, UPDATE and SELECT field lists are refused. Backends without a native count scan the matching objects in memory, under the aggregation fallback policy. Counts bypass the model permissions: see countModelWithPermissions in @webda/core for a client total.

Parameters​

deleteMany()​

deleteMany(statement, params?): Promise<number>

Defined in: packages/models/src/repositories/repository.ts:218

Delete every object matching a DELETE [WHERE ...] [LIMIT n] statement, in bulk

Bulk operations bypass the model layer: no per-object repository event (Delete/Deleted), no model hook, no behaviour and no validation run, and no permission (canAct) is checked. Repositories are trusted internal APIs: application code exposing a bulk statement to clients must check permissions itself.

Stores use their native batch operation when they have one, otherwise the matching keys are collected first (up to LIMIT) and deleted with the store's per-key primitive.

Parameters​

Returns​

the number of objects deleted

Throws​

if the statement is not a DELETE

updateMany()​

updateMany(statement, params?): Promise<number>

Defined in: packages/models/src/repositories/repository.ts:236

Update every object matching an UPDATE SET a = v, ... [WHERE ...] [LIMIT n] statement, in bulk

Bulk operations bypass the model layer: no per-object repository event (Patch/Patched/Updated), no model hook, no behaviour and no validation run, and no permission (canAct) is checked. Repositories are trusted internal APIs: application code exposing a bulk statement to clients must check permissions itself.

SET targets may not be a primary key field nor a private (__) field, and must be fields of the model when its metadata lists them. Dotted targets (profile.verified) set a nested value, creating the intermediate objects. Each matching object is updated once, even when the SET changes a field of the WHERE.

Parameters​

statement​

WebdaQLStatement<InstanceType<T>> | Query

the UPDATE statement, optionally with ? or :name placeholders, or its parsed form

params?​

QueryParameters

values for the placeholders: an array for ?, an object for :name

Returns​

Promise<number>

the number of objects updated

Throws​

if the statement is not an UPDATE, or a SET target is refused
