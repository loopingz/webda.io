UserKeys

@webda/core

Class: UserKeys

Defined in: packages/core/src/models/userkeys.model.ts:271

End-to-end encryption keys of a user (User.keys): public keys in clear, the encrypted keyring holding every private key and its escrows, and the devices holding the keyring

The private keys never reach the server in clear: the keyring (PKCS#8 keys by kid) is encrypted on the client with a random keyring key, itself wrapped by KEKs the server never sees (escrows: Argon2id/PBKDF2 of the password or of a recovery code; devices: WebAuthn PRF, OS keystore or passcode, kept locally). See src/sealed/ for the formats.

Actions, exposed as User.Keys.<Action>, are authorised by the owner canAct(context, "keys.<action>") (the user only, for User). __keyring and __escrows are server-only: getEscrow is the only way out of an escrow, to the owner, throttled on the owner attempts _escrowAttempts/_lastEscrowAttemptAt and audited by the operation events (Webda.OperationSuccess/Webda.OperationFailure). Opening an escrow happens on the client, so a fetch cannot be known to have succeeded: every fetch counts and nothing resets the counter, the lockout decays after escrowLockout. getKeyring serves the encrypted keyring alone, unthrottled: it opens nothing without the keyring key.

Every action requires a recent authentication (session authAt younger than reauthMaxAge) and, when the user has MFA enabled, a verified MFA login (session mfa: "verified").

Only the keys attribute is written (a patch): a whole-document save would overwrite the attempts counter incremented concurrently by getEscrow.
